# VirtuaPet Phase 3 Implementation Prompt

Continue the VirtuaPet repository from the accepted Phase 2 engineering baseline. Build Phase 3 as an isolated veterinary clinical digital-twin validation system for one narrowly approved intended use. Do not begin broad multi-procedure development until the clinical owner defines the species, anatomy, modality, acquisition limits, planning task, users, exclusions, and procedure-specific tolerances.

First inspect the repository, `HANDOFF.md`, the Phase 2 acceptance report, architecture specification, threat model, migrations, contracts, tests, and Git history. Preserve unrelated work and all established names and boundaries. Keep SugarDaddy.lgbt legally and operationally separate. Keep GibiWorld as the Unity and AR runtime. Use Layer8 for policy and human escalation only through authenticated, signed, auditable decisions.

Implement an imaging workspace or service with strict contracts for Study, Series, Volume, Segmentation, Mesh, Clinical Model, Plan, Rehearsal Session, Quality Result, Correction, Approval, Rejection, and Audit Event. Add secure DICOM and DICOMweb ingestion; quarantine; malware and archive-bomb protection; transfer syntax, modality, slice, spacing, orientation, patient, study, series, and laterality validation; controlled de-identification for validation datasets; immutable source hashing; and explicit failure states. Never silently combine patients, studies, sides, or incompatible series.

Implement a reproducible processing pipeline from validated series to volume, segmentation, clinician correction, surface extraction, topology repair, units and coordinate preservation, quantitative quality assurance, signed GLB packaging, and an entitlement-controlled GibiWorld manifest. Store complete parent-child lineage, tool and model versions, parameters, operator, timestamps, units, coordinate frames, uncertainty, corrections, approvals, and rollback targets. Derived artifacts are immutable; a correction creates a new version.

Build a source-linked clinical review interface that shows DICOM alongside derived anatomy, laterality, scale, quality results, warnings, uncertainty, version history, and approval controls. It must work without implying diagnosis or autonomous surgical guidance. Only clinician-approved models may enter rehearsal. GibiWorld must reject missing signatures, mismatched patient or laterality, invalid scale, expired entitlement, unsupported device profiles, and superseded versions.

Create a validation harness and dataset manifest that separates training, tuning, and holdout data by patient and site. Report performance by species, breed or body-size group, scanner or site, acquisition protocol, pathology, and intended use. Define Dice or overlap only per structure; also measure 95th-percentile surface distance, landmark error, linear measurement error, topology defects, missing critical structures, clinician correction time, approval rate, processing time, rehearsal task completion, and usability. Do not claim a universal segmentation score.

The minimum cross-cutting targets are: 100 percent patient, study, series, laterality, units, and orientation preservation; zero patient or laterality mismatch; 100 percent source-to-rendered-structure traceability; 100 percent veterinarian approval before rehearsal; 95 percent of approved linear measurements within 2 mm or 3 percent, whichever is greater, unless the clinical owner defines a stricter limit; critical-surface 95th-percentile error at or below 2 mm unless stricter; at least 90 percent completion of defined rehearsal tasks without assistance; and median System Usability Scale of at least 80. Procedure-specific gates may only be stricter.

Add unit, contract, API, repository, migration, integration, security, malicious-file, deterministic-processing, lineage, versioning, signature, entitlement, clinical-accuracy, subgroup, correction, and rollback tests. Use synthetic DICOM only for engineering smoke tests. Phase 3 cannot close without an approved validation protocol, governed representative data, independent holdout results, veterinary review, complete traceability, and documented failures.

Update the architecture specification, threat model, README, HANDOFF, API documentation, migration records, and a detailed Phase 3 acceptance report. The acceptance report must separate implemented code, local tests, CI, synthetic imaging evidence, representative-data validation, clinician approval, GibiWorld device verification, deployment, and production authorization.

Before closeout, run type checks, all tests, builds, dependency and secret scans, PostgreSQL migrations and round trips, imaging validation suites, and clean Git checks. Inspect every changed file, commit with a focused message, push to `robs46859-eng/virtuapet`, wait for CI, verify the remote commit equals local HEAD, and report exact remaining clinical, device, deployment, and production blockers. Do not declare clinical effectiveness, production deployment, or Phase 3 acceptance without fresh evidence for each claim.
