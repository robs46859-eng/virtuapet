## Boundary and call order

1. VirtuaPet verifies the user's OIDC token.
2. The integration context helper checks the active organization membership in VirtuaPet's repository. Header/JWT role claims do not confer organization roles.
3. The owning route checks resource ownership and consent for the particular requested operation. A policy decision is not a substitute for these checks.
4. The server calls `authorize(context, { action, resource, purpose, requiredEntitlements })` with fixed or validated operation identifiers. It must not let a caller choose a cheaper purpose/action instead of the actual operation.
5. The adapter sends a fresh request nonce plus caller, tenant, correlation, action, resource, purpose, and required entitlements. User access tokens, database credentials, role claims, patient records, and source DICOM are not forwarded.
6. Only a correctly signed, current, exact-match **allow** with all required entitlements and no unmet obligations succeeds. The owning route must consume it immediately for that operation. Deny, timeout, missing configuration, bad signature, changed tenant, replay, or uncertainty fails closed.

The adapter does not itself approve clinical use, create a subscription, charge a card, write a durable audit ledger, enforce distributed quotas, or perform the protected resource operation. Those remain separate gates. No success result should be cached or handed to a browser as lasting authorization.

## Proposed wire contract

Protocol identifier: `virtuapet.layer8.policy.v1.proposed`. Before enabling, the Layer8 owner must approve this protocol or supply its actual contract for an adapter revision.

Use an explicitly configured HTTPS endpoint with POST. VirtuaPet supplies a dedicated, narrowly scoped server-to-server bearer credential. The endpoint is operator configuration, never a user-provided URL. IP literals, unqualified hosts, localhost, and common internal/reserved suffixes are rejected. Operator review and an outbound network allowlist are still needed: string checks alone cannot prevent a public hostname from resolving to a private address. Credentials are not sent through redirects; redirects are rejected.

Request fields:

| Field | Source and meaning |
| --- | --- |
| `protocol` | Exact proposed protocol identifier |
| `requestId` | New unpredictable UUID for every policy call; prevents reuse of a captured response |
| `subject` | Verified VirtuaPet user UUID |
| `tenantId` | Server-validated organization UUID |
| `correlationId` | Request correlation UUID generated by VirtuaPet |
| `action`, `resource`, `purpose` | Bound operation identifiers, each 1–256 characters |
| `requiredEntitlements` | Explicit entitlement names needed for that operation, at most 32 |

The response is JSON with exactly one field: `{ "decisionToken": "<compact signed JWT>" }`. This JWT is signed asymmetrically with **ES256/P-256** or **RS256**. Its protected header must include `typ: "vp-layer8-policy+jwt"` and a `kid` matching an operator-pinned public JWK. HMAC and private signing material are not accepted in this verifier configuration.

Required signed claims are `iss`, `aud`, `sub`, `iat`, `exp`, `jti`, `protocol`, `tenantId`, `correlationId`, `requestId`, `action`, `resource`, `purpose`, `policyVersion`, `outcome`, `entitlements`, and `obligations`. `nbf` is optional and enforced. Unknown claims fail closed for this version. `sub` must equal request `subject`; all other binding fields must match exactly. `jti` is the UUID decision identifier. Outcome is `allow` or `deny`.

Evidence lasts no longer than 60 seconds from issuance, must already be valid, and must not be expired. There is no clock-skew grace period. Clock synchronization is an operational prerequisite. All required entitlements must be included. The current adapter supports no obligations: any nonempty obligations list is denied until a specific obligation handler is implemented and tested.

The returned internal decision summary contains only the decision ID, policy version, allowed entitlements, expiry, outcome, and correlation ID. It does not include the provider token or service credential.

## Configuration and operations

| Variable | Required behavior |
| --- | --- |
| `LAYER8_POLICY_ENABLED` | Only exact `true` enables calls; otherwise disabled |
| `LAYER8_POLICY_ENDPOINT` | Verified HTTPS provider endpoint; no embedded credential, query, fragment, or nonstandard port |
| `LAYER8_POLICY_SERVICE_TOKEN` | Dedicated server credential from the secret store; never expose through web build variables |
| `LAYER8_POLICY_ISSUER` | Exact expected JWT issuer |
| `LAYER8_POLICY_AUDIENCE` | Exact expected VirtuaPet audience |
| `LAYER8_POLICY_PUBLIC_JWKS` | JSON public JWK set with 1–8 uniquely identified ES256 or RS256 verification keys |

Key rotation is explicit: publish the new public key alongside the old one in configuration, deploy consumers, rotate the provider signer, then remove the old key after all short-lived evidence expires. There is no automatic network JWK lookup.

Default timeout is 5 seconds for the whole operation, including response body consumption and validation. Default maximum response is 16 KiB; streamed size is checked even when Content-Length is absent. The adapter never retries policy requests and never falls back to an allow. Transport and validation errors are safe codes without upstream bodies or secrets. Disabled/unconfigured/unavailable/invalid evidence returns a service failure to callers; explicit denial or unmet obligations returns forbidden. The status method reports configuration state only, **not provider health or verified interoperability**; valid enabled settings return `configured_unverified`. It makes no health-probe request.

There is no distributed circuit breaker, rate limiter, durable decision audit, or production reconciliation in this first adapter. Keep disabled until those operational requirements and the actual provider contract are reviewed for the intended pilot. Never log full bearer tokens or JWTs. Record decision ID, policy version, tenant, safe outcome code, correlation ID and timing in an access-controlled audit system when wiring real execution.

## Verification and remaining acceptance

Run `npm test --workspace @virtuapet/api -- src/integrations/layer8.test.ts`. Tests use generated test-only asymmetric keys and fake transport, without real accounts or billing. They cover successful exact binding; disabled/missing/unsafe configuration; tenant/subject/action/resource/purpose/nonce/correlation mismatch; stale/future/overlong evidence; bad keys/signatures; unknown obligations; missing entitlements; malicious/malformed/oversized responses; redirect rejection; and total-operation timeout.

Before calling the integration connected:

- Identify the production Layer8 policy/billing service and confirm its endpoint and versioned contract; the inspected operator prototype does not supply them.
- Preserve the explicit server-owned mapping between VirtuaPet organization UUIDs and Layer8 tenant IDs; the systems do not require or assume matching identifiers.
- Obtain a dedicated minimum-scope credential and pinned public keys through approved secret management.
- Have Layer8 reject forged subjects/tenants and authorize this service only for its assigned tenants. A shared service credential alone is not proof of tenant authority.
- Run a staging test with two real test tenants and show denial across tenant boundaries, entitlement removal, expiry, revoked credentials, and provider outage.
- Add durable audit, distributed abuse limits, operational alerting, and any required obligation handlers before a production rollout.
- Reuse existing Layer8/Stripe subscription and signed-webhook ownership. This change intentionally does not duplicate payment or webhook logic.

The gateway productization and routing skills guided the narrow control-plane boundary, safe error handling, bounded calls, and honest rollout status. Existing VirtuaPet Node/Fastify architecture is preserved.
